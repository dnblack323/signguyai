Sign Guy AI Rebuild Plan - Add-On Strategy
Page 2
1. Core Decision
The rebuild should be structured around a strong base platform with optional paid add-on modules. The base app should
run the core sign shop business. Larger specialized workflows should be built as gated add-ons that reuse the same
shared systems.
The first major add-on should be Webstores. The second major add-on should likely be Wrap Command Center,
because both modules use many of the same core systems needed throughout the full app.
The app should not be rebuilt as one giant all-in-one feature blob. It should be built with clean feature
gating from the beginning so add-ons can be enabled, disabled, sold separately, or included in higher plans
later.
2. Base App
The base app should include the everyday tools needed to run a sign shop. It must be useful on its own without requiring
paid add-ons. Add-ons should enhance the system, not make the base app feel incomplete.
Base App Should Include
 Main dashboard / home dashboard
 
 Core navigation and shared layout
 
 Customers / CRM

 Basic app settings
 
 Shared ribbon system
 
 Shared permissions / roles
 
 Feature flag and add-on system
 
3. Shared Core Systems
All major modules and add-ons should use the same shared core systems instead of creating duplicate versions inside
each module.

13. Final Product Packaging Concept
Base Plan: Run the sign shop.
Webstores Add-On: Sell online with fundraiser, B2B, event, and future store-building workflows.
Wrap Command Center: Manage wraps from intake to install.
Smart Pricing Pro: Price smarter with advanced pricing, live calculations, local market research, and AI analysis.
AI Tools Pro: Use advanced AI tools and higher AI usage limits.
SMS/MMS Messaging: Text customers, send reminders, and manage conversations.
Production Timing Pro: Track production time by item, stage, employee, and bottleneck.
Training Pro: Train employees and certify them before using expensive equipment.
14. Final Decision
The rebuild should not treat Webstores, Wrap Command Center, Smart Pricing, SMS, AI Tools, and Production Timing
as random features scattered throughout the app. They should be planned as clean, optional add-on modules that reuse
the same shared core systems.
Build the main shell and shared core systems first, then build Webstores as the first gated add-on, then
Wrap Command Center as the second gated add-on.
