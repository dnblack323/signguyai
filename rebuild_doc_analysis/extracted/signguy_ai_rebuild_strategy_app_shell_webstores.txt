 SignGuy AI Rebuild Strategy Update
 App Shell First + Webstores as the First Full Expansion Module
Purpose: This section is written to be merged into the current rebuild plan. It explains why the rebuild
should start with the reusable app shell, then build Webstores deeply as the first complete add-on, while
converting anything reusable into shared platform infrastructure instead of burying it inside one module.
1. Decision
The new SignGuy AI rebuild should follow an App Shell + Expansion Module strategy.
Instead of rebuilding every feature at once, the system should first establish a strong reusable application
foundation. After the shell is stable, the first complete expansion module should be Webstores.
This is the correct first module because Webstores naturally requires many systems the rest of the app
will also use: questionnaires, portals, document uploads, customer emails, AI summaries, approvals,
products, pricing, payment workflows, and owner/customer access.
2. Core Principle
Every Webstore feature should be evaluated with this question:
Is this truly only a Webstore feature, or is it a platform feature that Webstores happens to use first?
If other modules will eventually need the same functionality, build it as a shared system from day one.

4. Phase 2: Webstores Expansion Module
Webstores should become the first complete production-ready expansion module. It should not be treated
as a small side feature. It should be built deeply enough to validate the shared platform systems.
Webstore Types
• Fundraiser Stores: donation percentages, checkout donations, goal tracking, progress bars, fundraiser
 reports, and campaign deadlines.
• Promotional Stores: race teams, influencers, local businesses, event brands, fan merchandise, and limited
 campaigns.
• B2B Stores: employee ordering, company stores, approved catalogs, internal purchasing, and
 customer-specific products.
• General Stores: standard ecommerce stores, public products, retail sales, and simple branded storefronts.
 
Webstore Setup Workflow
• 1. Store Creation: Choose store type, assign customer, enter core store information, and define ownership.
 
• 2. Questionnaire Delivery: Send automated onboarding email with questionnaire links and upload
 requests.
• 3. Customer Completion: Customer submits logos, colors, brand guidelines, product requests, store
 preferences, and campaign details.
• 4. AI Review: AI generates a summary, action items, recommended products, and potential issues while
 preserving the original responses.
• 5. Admin Review: Manager reviews questionnaire, AI summary, uploaded files, and missing requirements.
 
• 6. Store Build: Manager configures products, pricing, categories, branding, payment settings, and launch
 settings.
• 7. Owner Approval: Store owner receives preview link and approval request before launch.
 
• 8. Launch: Store goes live with QR code, share link, domain/slug, promo tools, and tracking.

10. Final Rebuild Rule
The objective is not simply to rebuild the current application. The objective is to create a scalable Sign
Shop Operating System where every new feature strengthens shared platform infrastructure that can be
reused throughout the ecosystem.
Every module should make the platform stronger. Nothing should be built only for one feature if it can be
reused elsewhere.
